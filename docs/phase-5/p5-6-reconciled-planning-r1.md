## Reconciled Authorization

The browser is never an authorization boundary. Server-authoritative RBAC
provides stable job capabilities and constrained ABAC refines each decision by
organization, department, purpose, resource, object state, assignment, session
assurance, policy revision, time bound, and separation-of-duty context. Missing,
unknown, stale, malformed, contradictory, or unsupported context denies by
default.

PostgreSQL row security independently enforces organization and department data
scope. API authorization and RLS must agree; disagreement denies and produces a
sanitized attributable security outcome. Navigation visibility, cached
capabilities, a privileged route, a deep link, a resource profile, or an
administrator label never grants authority. Cross-department existence remains
undisclosed.

## Reconciled Administrative Lifecycle

Every consequential future change is a typed proposal with exact subject,
schema, current revision, strong ETag, proposed values, validation state,
before/after comparison, dependency graph, blast radius, policy revision,
requester, reason, expiry, and idempotency identity. The lifecycle separates
draft, validation, review, approval, schedule, effect, executor result,
supersession, correction, rejection, expiry, and cancellation.

Static and dynamic separation of duty denies self-approval and incompatible
role combinations. Approval never means execution. A future executor must
revalidate current policy, scope, dependencies, ETag, revision, time, and kill
switches and return an immutable receipt. Rollback is a new typed revision, not
history deletion. P5.6 implements only generated, non-effective proposals and
receipts; Apply, Execute, Deploy, Activate, Delete, Restore, Rotate, Direct
Control, and equivalent operative actions remain absent.

## Reconciled Privileged Access

Step-up-required and break-glass-unavailable are typed states. They do not fall
back to weaker authentication or broader access. Unknown assurance, stale

failure all stop closed.
