# P5.0 Reconciled Planning R2

## Change From R1

R2 preserves the complete R1 architecture and all twelve owner decisions. It
adds one owner-directed clarification:
`D-P5.0-GIS-ADOPTION-001`.

The existing Gujarat GIS is elevated from a reusable visual source to the
canonical Phase 5 GIS operator-experience baseline. Its current layout,
filters, layers, selection flow, local clustering, responsive drawers, safety
labels, and approved live-preview workflow must be adopted substantially and
protected by parity evidence.

## Relationship To `D-P5.0-005:D`

The selected MapLibre 2D plus guarded optional 3D architecture is unchanged.
MapLibre is the target renderer behind the preserved experience. The migration
must be renderer-neutral and parity-first; optional 3D remains subordinate to
authoritative 2D and accessible list equivalents.

## Delivery Impact

- P5.0 must define the GIS parity matrix and source-provenance boundary.
- P5.1 must provide shared GIS contracts, capabilities, localization,
  accessibility primitives, and test infrastructure.
- P5.2 must reuse the existing GIS summary and situational-awareness patterns
  in the Command Center.
- P5.3 must migrate and extend the full GIS workspace with behavioral and
  visual parity evidence.
- P5.4 and P5.5 may add intelligence, alert, investigation, evidence,
  correction, and temporal overlays without displacing the camera workflow.
- P5.6 must expose resource-profile and degradation controls without reducing
  policy, freshness, correction, or accessibility semantics.
- P5.7 must validate the complete GIS parity matrix across desktop, tablet,
  mobile, localization, accessibility, browser, and C1/C10/C50 profiles.

The frozen Phase 5 weights are not changed. Planning remains **8/8
(100.0000%)** and product progress remains **0/100 (0.0000%)** because this
directive authorizes no implementation.

## Gate

R2 supersedes R1 only as the current non-effective planning proposal. R1 and
all earlier records remain immutable. R2 requires exact owner acceptance
before an implementation/start package may be prepared.
