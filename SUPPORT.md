# Support

Use GitHub Issues for reproducible defects, approved feature work, architecture decisions, risk tracking, and review questions. Select the closest structured issue form and remove all sensitive data before submission.

Before filing an operations issue:

1. Check `/health/ready` and the relevant adapter status endpoint.
2. Capture sanitized error text and the exact local commit SHA.
3. State whether the failure affects API readiness, catalogue access, WHEP signalling, or decoded browser media.
4. Confirm whether recording and analytics were disabled or explicitly in scope.

Use a private security advisory for credentials, private locators, authorization bypasses, sensitive camera data, or exploitable weaknesses. GitHub Issues are not an emergency operations channel and should never contain production secrets or footage.
